# P4.3 — Biblioteca de bloques React + design system + compositor

> Sub-plan de [P4-composable-blocks.md](./P4-composable-blocks.md) (entregable 2 / fase 2). Leé el padre §Entregable 2.

## Objetivo
Un componente React por `BlockType`, tipado por su `data` del PagePlan, con 1 variante mínima cada uno (las extra son opcionales). Compositor `<Page plan tokens/>` que emite HTML vía el pipeline de P4.1.

## Contexto necesario
- P4.1 (`render.tsx`), P4.2 (`PagePlan`, `BlockType`).
- Padre P4 §Entregable 2 (lista de bloques y variantes), §"Política de datos placeholder".

## Entregables
1. `src/blocks/<Tipo>.tsx` para cada BlockType. Mínimo 1 variante funcional por bloque.
2. `src/blocks/system.ts(x)`: design system compartido (escala tipográfica, espaciado, color, motion, estados hover/focus) mapeando design tokens a CSS vars / theme Tailwind.
3. Compositor: `plan.blocks.map(renderBlock)` → `<Page>`. Bloques desconocidos: omitir con warning, no romper.
4. **Sourcing premium**: arrancar cada bloque desde shadcn/Aceternity (CLI shadcn) o MCP `magic` (`getRegistryItem includeSource:true`) y **portar** a tokens+tipos. No pegar crudo.
5. Reglas de datos: `results`/`team`/`testimonials` respetan LG-01/AC-02 (placeholder marcado o omitir, nunca cifras/reseñas inventadas). `footer` incluye NAP + JSON-LD `schema.org/LegalService` + disclaimer.

## Gates
- Build + lint OK.
- `vitest run`: test de render por bloque (HTML contiene marcadores esperados), test del compositor con un PagePlan de ≥6 bloques.

## Criterio de parada
Todos los bloques renderizan, compositor arma página completa desde un PagePlan fixture, gates verdes.
