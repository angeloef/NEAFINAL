# P4.1 — Setup React/Tailwind en `@lpb/worker-assembly`

> Sub-plan de [P4-composable-blocks.md](./P4-composable-blocks.md) (fase 0). Leé el padre para el porqué.
> Solo esta fase: dejar el pipeline de render estático listo. NO migrar secciones todavía.

## Objetivo
Habilitar render de componentes React a HTML estático autocontenido en `worker-assembly`, con Tailwind compilado a CSS inline. Sin runtime JS salvo lo imprescindible.

## Contexto necesario
- `packages/worker-assembly/package.json`, `src/index.ts`, `src/layout.ts` (template string actual; NO borrar, convive).
- Padre P4 §"Plan de ejecución" punto 0 y §"Notas de implementación".

## Entregables
1. Deps: `react`, `react-dom` (+ `@types/*`), `tailwindcss`. Pipeline: `renderToStaticMarkup` para emitir HTML; Tailwind → CSS estático inyectado en `<head>`.
2. `src/render.tsx` (o similar): función `renderReactPage(node) => htmlString` que envuelve con `<!doctype html>` + `<head>` con el CSS compilado.
3. Smoke test (`test/render.test.ts`): un componente trivial `<div className="text-xl">Hola</div>` → HTML contiene el markup y la clase Tailwind resuelta (o la clase presente + CSS en head).
4. Mantener tests actuales de assembly verdes.

## Gates
- `corepack pnpm --filter @lpb/worker-assembly build` OK.
- `vitest run` verde (smoke + tests existentes).

## Criterio de parada
Build verde, smoke test pasa, secciones string-template actuales intactas.
