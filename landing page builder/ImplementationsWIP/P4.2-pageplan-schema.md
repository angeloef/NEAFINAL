## Objetivo
Nuevo contrato `PagePlan` que reemplaza el flujo "texto para slots" por bloques componibles `{ type, variant, data }`. Es la base de las fases siguientes.

## Contexto necesario
- `packages/contracts/src/index.ts`, `src/schemas/` (ver cómo está definido `Copy`), `src/jsonSchema.ts`.
- Padre P4 §Entregable 1.

## Entregables
1. `BlockType` enum: `hero | trust_bar | areas | about | process | results | team | testimonials | faq | cta_band | contact | footer`.
2. `PageBlock = { type: BlockType, variant: string, data: <sub-schema por type> }`. Cada `data` con su sub-schema Zod. Campos de dato fáctico conservan `clase` (VERIFICADO/PLANTILLA) como en `Copy`.
3. `PagePlan = { mission_id, blocks: PageBlock[], meta: { title, description } }`.
4. Export desde `index.ts` + entrada en JSON Schema (`jsonSchema.ts`) si el resto del sistema lo consume así.
5. Mantener `Copy` intacto (deprecado, no borrar) para no romper tests existentes.

## Gates
